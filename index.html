Your first distributed-systems problem

Continue in Chapter 1
1 · PredictA reply never arrives

A client sends PUT x=1. The server receives it, changes its state, sends OK, and the reply is lost. The client sees only a timeout. Before continuing, decide whether retrying is safe.

2 · ReasonThe timeout is not the remote history

The same timeout could mean the request never arrived, the server crashed before executing it, the effect completed but the reply was lost, or the reply is merely delayed. One local observation is compatible with several remote executions.

3 · Carry forwardDesign for uncertainty

This is why later chapters need request identity, idempotency, failure models, replicated state, consensus, durable recovery, and evidence. Distributed systems begin when you stop treating “no response” as “nothing happened.”
