    Communication II — Messaging, Dissemination, and Overlays — Guided Practice

    Core practice: Complete cases 0, 0b, 3, 4, 7, 11, 15, 16, and 17. Then use the Practice target at the end of this page as the stop criterion. The remaining cases are a reusable retrieval/challenge bank, not a checklist you must finish before the lab.

    Complete these before the lab. First choose the communication model; then, for decentralized communication, keep logical overlay structure separate from physical network structure.

    0. Communication-model checkpoint

    Section titled “0. Communication-model checkpoint”

    For each scenario, choose the most natural starting model and justify the choice:

    • a client needs an immediate answer from one known service;
    • a producer creates work while consumers may be offline;
    • one event should reach every interested subscriber;
    • membership updates should spread through a large changing group;
    • a peer knows a key but not the peer currently responsible for it.

    Compare RPC, queue, publish/subscribe, gossip, and structured overlay.

    For each choice state:

    • who knows the destination;
    • whether the sender waits;
    • what acknowledgement means;
    • whether duplicate delivery is possible;
    • where undelivered information must live.

    0b. Redelivery trace

    Section titled “0b. Redelivery trace”

    A consumer processes message 81, changes state, and crashes before acknowledging the message.

    Predict what an at-least-once queue may do after restart. What identifier or application rule is needed if applying message 81 twice is unsafe?

    Connect the answer to Chapter 4’s request-ID and idempotency reasoning.

    1. Dimensions of decentralization

    Section titled “1. Dimensions of decentralization”

    For a hypothetical P2P file system, classify whether each mechanism is centralized or distributed:

    • identity issuance;
    • bootstrap seed list;
    • peer membership;
    • file-chunk placement;
    • routing;
    • storage;
    • trust/authentication.

    Explain why one centralized bootstrap component does not automatically make every operation centralized.

    2. Overlay versus physical route

    Section titled “2. Overlay versus physical route”

    Logical lookup:

    A → D → H

    Suppose A→D crosses 11 IP routers and D→H crosses 7.

    How many overlay hops occurred? How many physical router hops occurred? Why are both metrics useful?

    3. Consistent-hash ownership

    Section titled “3. Consistent-hash ownership”

    Ring positions 0..99 contain nodes at:

    10, 40, 70

    Use first-clockwise-owner semantics. Find owners of keys:

    5, 12, 39, 40, 68, 90

    Then add node 25 and identify which ownership interval changes.

    4. Successor-only lookup

    Section titled “4. Successor-only lookup”

    Use nodes:

    4, 12, 20, 35, 52, 60

    Starting at 4, trace a successor-only lookup for key 50.

    How many hops? What is the worst-case scaling as the ring grows?

    5. Shortcut lookup

    Section titled “5. Shortcut lookup”

    Give node 4 additional useful shortcuts to 20 and 35. Trace key 50 again.

    Explain the geometric intuition behind Chord-style fingers.

    6. Lookup correctness versus efficiency

    Section titled “6. Lookup correctness versus efficiency”

    Design two routing algorithms:

    • one that always succeeds but may require O(N) hops;
    • one using shortcuts that is faster when routing state is fresh.

    List separate metrics for correctness and efficiency.

    7. Join transition

    Section titled “7. Join transition”

    Ring:

    10 → 40 → 70 → 10

    Node 25 joins.

    List:

    • predecessor/successor changes;
    • key range movement;
    • routing entries that may remain stale temporarily;
    • one lookup that could encounter stale information.

    8. Abrupt departure

    Section titled “8. Abrupt departure”

    Node 40 crashes without notification.

    What state must neighbors/routing tables detect or repair? Why is this not equivalent to graceful leave?

    9. Replication on a DHT

    Section titled “9. Replication on a DHT”

    A key is stored on its owner plus two successors.

    Owner fails.

    What improves? What consistency/recovery question remains unresolved?

    Explain why placement does not define update consistency.

    10. Kademlia XOR distance

    Section titled “10. Kademlia XOR distance”

    Use 4-bit IDs:

    A=0011
B=1011
C=0110
key=1110

    Compute XOR distance from each node to the key. Which is closest numerically under XOR metric?

    Explain why this differs conceptually from clockwise ring distance.

    11. Gossip rounds

    Section titled “11. Gossip rounds”

    Eight nodes begin with one node informed of update E.

    Assume an idealized no-collision push where every informed node contacts one uninformed node per round.

    How many rounds would full dissemination require in the ideal case?

    Then explain why real randomized gossip converges differently.

    12. Push versus pull

    Section titled “12. Push versus pull”

    Give one scenario where push is efficient early in dissemination and one where pull helps late convergence. Explain the benefit of push-pull.

    13. Message loss

    Section titled “13. Message loss”

    Why can repeated gossip still converge despite some lost messages? What cost pays for that resilience?

    14. Statistical evaluation

    Section titled “14. Statistical evaluation”

    A gossip experiment produces rounds-to-90%-coverage:

    6, 8, 7, 11, 6, 9, 7, 7, 15, 8

    Compute/report a sensible summary beyond the mean. Why should one deterministic run not be the only evaluation?

    15. Failure suspicion

    Section titled “15. Failure suspicion”

    Node B times out while probing A.

    Compare:

    B immediately declares A DEAD

    with:

    B marks A SUSPECT and asks C/D for indirect evidence

    What trade-off changes?

    16. Incarnation refutation

    Section titled “16. Incarnation refutation”

    Network contains rumor:

    A incarnation 7 = SUSPECT

    A announces:

    A incarnation 8 = ALIVE

    Which should win and why? What happens if an old incarnation-6 rumor arrives later?

    17. Central registry comparison

    Section titled “17. Central registry comparison”

    For a 30-node controlled teaching cluster, compare:

    • replicated registry;
    • DHT;
    • gossip membership.

    Score each qualitatively for:

    • implementation complexity;
    • authoritative lookup;
    • rich queries;
    • churn scalability;
    • central dependency;
    • maintenance traffic.

    Which would you choose and why?

    18. Agent capability discovery

    Section titled “18. Agent capability discovery”

    P06 needs:

    find providers of capability=image-resize

    Compare a central index, capability-keyed DHT, and gossip-local cache. Which supports arbitrary multi-attribute queries most naturally? Which avoids one permanent directory?

    19. DHT trust assumption

    Section titled “19. DHT trust assumption”

    A malicious peer lies about ownership and routes every lookup toward itself.

    Does the basic crash-fault DHT design handle this? Which later course topic is needed?

    20. AI audit

    Section titled “20. AI audit”

    Ask an AI assistant to implement or analyze a DHT/gossip algorithm. Look for:

    • node ID/address conflation;
    • no join/leave handling;
    • one timeout → DEAD;
    • stale rumor overwriting newer incarnation;
    • assuming one gossip run proves convergence;
    • equating DHT ownership with consistent replication.

    For one discovered issue, design a reproducible experiment that exposes it.

    Practice target

    Section titled “Practice target”

    You are ready for the lab when you can answer:

    For this discovery problem, why is a central registry, DHT, or gossip protocol the appropriate information structure—and what stale-state/maintenance cost follows from that choice?
