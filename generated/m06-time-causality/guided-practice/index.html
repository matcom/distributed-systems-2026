    Coordination I — Time, Events, and Causality

    Part IIChapter 6Guided practice

    1. Overview
    2. Lesson
    3. Practice
    4. Check
    5. Lab
    6. Optional
    7. Deep dive
    8. Connections
    9. Further learning

    Core practice: Complete cases 1, 2, 3, 4, 5, 7, 8, and 12. Then use the Practice target at the end of this page as the stop criterion. The remaining cases are a reusable retrieval/challenge bank, not a checklist you must finish before the lab.

    Complete these before the lab. Draw causal paths; do not infer order from page layout or wall-clock timestamps alone.

    1. Contradictory timestampsCore

    Section titled “1. Contradictory timestamps”

    Logs show:

    A 12:00:05.300 send M1
B 12:00:05.100 receive M1

    What can you conclude about causality? What can you conclude about clock synchronization? What can you not conclude about exact clock offset?

    2. Happened-before graphCore

    Section titled “2. Happened-before graph”

    For:

    P1: a --send m---------------- d
P2: b --------receive m--c--send n
P3: e ----------------------receive n--f

    Classify these pairs as causal, reverse-causal, concurrent, or insufficient information:

    • a and c;
    • b and send(m);
    • c and f;
    • d and e;
    • send(n) and f.

    Justify each with a causal path or its absence.

    3. Lamport computationCore

    Section titled “3. Lamport computation”

    All clocks start at 0.

    P1: a, send m to P2, d
P2: b, receive m, send n to P3
P3: e, receive n, f

    Compute a valid Lamport timestamp for each event using one consistent increment convention.

    4. Invalid Lamport inferenceCore

    Section titled “4. Invalid Lamport inference”

    Events have:

    L(a)=4
L(b)=9

    Construct an execution where a and b are concurrent. Explain why scalar timestamp order does not prove happened-before.

    5. Vector comparisonCore

    Section titled “5. Vector comparison”

    Classify each pair:

    A=[2,1,0]  B=[3,1,0]
C=[4,2,0]  D=[3,3,0]
E=[1,4,2]  F=[1,4,2]

    For equal vectors, explain why additional event identity may still be needed rather than treating two records as automatically the same event.

    6. Concurrent replica writesChallenge bank

    Section titled “6. Concurrent replica writes”

    Two replicas share version [1,0], disconnect, then produce [2,0] and [1,1].

    Explain what vector clocks reveal and what they do not tell you about conflict resolution.

    7. Wall time versus monotonic timeCore

    Section titled “7. Wall time versus monotonic time”

    Choose the appropriate mechanism for:

    • measuring RPC duration;
    • displaying an approximate human timestamp;
    • deciding whether event A causally influenced B;
    • implementing a local 500 ms timeout.

    Explain each choice.

    8. Total order versus causal orderCore

    Section titled “8. Total order versus causal order”

    Two concurrent events have Lamport time 7 on P1 and P2. A system orders them by (timestamp, process ID).

    Why is that useful? Why does it not prove that P1’s event caused P2’s event?

    9. Delivery guaranteesChallenge bank

    Section titled “9. Delivery guarantees”

    Distinguish FIFO, causal, and total-order delivery using three messages from two senders. Construct one delivery order allowed by FIFO but not by causal ordering.

    10. Trace schemaChallenge bank

    Section titled “10. Trace schema”

    Design a trace record containing enough fields to reconstruct a three-process message workflow while clocks disagree.

    For each field, state what question it answers.

    11. Lease misconceptionChallenge bank

    Section titled “11. Lease misconception”

    A student proposes a Lamport clock to expire a worker lease after 15 seconds.

    Explain why this is invalid. Which time source should measure local elapsed duration, and which additional distributed assumptions still matter?

    12. Causal consistency storyCore

    Section titled “12. Causal consistency story”

    Alice publishes A. Bob reads A and publishes B referencing A. Carol independently publishes C.

    Draw the causal constraints. Which relative orders are required and which can vary across replicas?

    13. AI-audited trace reconstructionChallenge bank

    Section titled “13. AI-audited trace reconstruction”

    Give an AI assistant a shuffled trace containing wall timestamps, message IDs, and Lamport clocks. Ask it to reconstruct the execution. Check every claimed causal edge manually and identify any edge inferred only from timestamp magnitude rather than an actual happened-before path.

    Practice target

    Section titled “Practice target”

    You are ready for the lab when you can explain both statements:

    a → b  implies  L(a) < L(b)

    but

    L(a) < L(b)  does not imply  a → b
