Replication and Consistency

When several nodes hold the same logical data, which histories may a client observe?

Replicate a small service and create stale reads, conflicting writes, and a partition. Use the resulting histories to define the guarantee instead of starting from labels. Then compare stronger coordination with convergence-oriented designs such as CRDTs.

Key ideas

Section titled “Key ideas”
  • reasons to replicate
  • primary/backup and leaderless replication
  • synchronous and asynchronous propagation
  • quorums
  • linearizability
  • sequential and causal consistency
  • client/session guarantees
  • eventual consistency and convergence
  • CAP trade-offs
  • CRDT intuition and merge laws

Laboratory transition

Section titled “Laboratory transition”

Run a replicated key/value service under lag, conflict, and partition. Classify the observed histories, then explain whether convergence alone would be sufficient for the application invariant.

Start here

Section titled “Start here”

Before you read: A write returns OK from replica R1. A later read from R2 returns the old value. Is the system wrong? State the guarantee you assumed before answering.

Bring forward: Causality, quorum intuition, naming/membership, and explicit client operation histories.

This chapter builds toward: The ability to classify histories and choose between coordinated replication and convergence-oriented data semantics.

What you will learn

Section titled “What you will learn”
  • Explain why replication creates consistency questions rather than only reliability benefits.
  • Classify observable histories under linearizable, sequential, causal, session, and eventual guarantees.
  • Compare primary/backup, synchronous/asynchronous, quorum, and leaderless replication.
  • Create and analyze stale-read, conflicting-write, and partition histories.
  • Explain when convergence-oriented merge rules such as CRDTs fit the application invariant.

Learn by working the question

Section titled “Learn by working the question”
  1. Write your answer to Start here before opening the full lesson.
  2. Read until the next prediction or trace, then stop and work it out before revealing the explanation.
  3. Treat guided practice as a practice bank, not a speed worksheet. Work the core traces until you can meet the chapter’s Practice target; return to the remaining cases for retrieval practice or instructor-assigned work.
  4. Use the knowledge check to find gaps, then enter the laboratory with a falsifiable prediction and name the evidence that could contradict it.
  5. Finish by explaining what the experiment established, what it did not establish, and how the result changes the evolving service.
