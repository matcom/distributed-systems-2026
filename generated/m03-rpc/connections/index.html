    Reference view. This page is optional context; return to the Lesson for the required path.

    Chapter 4 is the first chapter where the course fully removes the communication convenience supplied by Ray. It connects the transport behavior learned in Computer Networks with the failure, retry, and state semantics needed by every distributed service later in this course.

    Computer Networks

    Section titled “Computer Networks”

    TCP/UDP provide communication substrates, not application completion guarantees. TCP can give an ordered reliable byte stream between surviving endpoints while the application still cannot know whether a remote side effect occurred after the response path fails.

    This is the point where networking concepts such as connection failure, delay, loss, congestion, DNS, and path changes become application-level distributed-systems questions.

    Operating Systems

    Section titled “Operating Systems”

    An RPC server is also a concurrent process. Sockets, goroutines/threads, timers, queues, file descriptors, cancellation, process crashes, and persistent writes determine how calls execute locally.

    A duplicate network request can race with the first attempt inside the server, so duplicate suppression itself requires correct local synchronization.

    Computer Architecture

    Section titled “Computer Architecture”

    Serialization, memory copies, system calls, cache behavior, encryption, context switching, and NIC/CPU interaction influence RPC latency and throughput. Large payloads can turn an apparently simple method into a data-movement problem.

    Later Distributed Systems modules

    Section titled “Later Distributed Systems modules”
    • Chapter 3: concurrent handlers and local races inside services.
    • Chapter 6: ordering distributed events when wall-clock timestamps are insufficient.
    • Chapter 10: failure detection and unreliable networks behind timeouts.
    • Chapter 9: retries of reads/writes interact with replica consistency.
    • Chapter 7–Chapter 10: consensus and replicated state machines make request deduplication part of replicated state.
    • Chapter 11: transactions define atomic boundaries for request records and side effects.
    • Chapter 12: retries, deadlines, queues, and backpressure become performance/observability problems.

    Final-project connection

    Section titled “Final-project connection”

    Phase 1 may express an operation as a Ray task or actor method. In Phase 2, you must state explicitly:

    wire contract
request identity
deadline
retry policy
idempotency / duplicate suppression
error model
persistence boundary
observability

    A native design is not complete merely because one service can call another. The project must explain what a failed call means and how uncertainty is resolved.
